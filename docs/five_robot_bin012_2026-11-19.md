# 五机0.12m垃圾桶：实物尺寸基准

按用户条件，将新独立场景的物理圆柱半径设为.12m，保持R=.4正五边形、原三条actor路径/速度、控制算法/硬DCBF、所有不确定性及执行/车体裕量、h=.22预测触发、N10/.1s和100ms截止。旧.18m场景、协议、全部结果不覆盖。入口`five_turtlebot3_cbf_bin012.launch`。仅改场景平面尺寸及评估匹配，不是算法创新。

新协议`cbf_five_bin012_protocol.yaml`：原运动/无故障/净距/终点恢复判据保持。实验前根据名义CPA与.13+.12=.25m物理代理半径重新固定角色：迎面/追越0、2、3号，斜向0、4号。斜向3号CPA距离.261698m、净距约.011698m，不再强求.13m侧移，但仍须安全、连续运动和恢复。旧.18场景角色和评价结果不变。增加物理尺寸和CPA角色匹配检查，错误场景不接受。

每台依旧只看本机雷达，圆弧拟合不读取设定.12的真值；该尺寸只用于Gazebo生成及独立评估。小目标远处回波更稀疏，保留原至少6点/弧长/精度门槛与回退，不放松拟合质量。controller、MPC、观测和误差公式源码保持父阶段一致。

本阶段先冻结242检查及参数预检，再按同一源码顺序运行追越/迎面/斜向seed211，各40s。所有失败保留，先判断单纯改物理尺寸后的效果，再开启另一个阶段修改算法，不把通过数量变化归因于算法进步。

这里仅对齐垃圾桶平面半径；场景仍使用原高.8m的运动学圆柱载体，未获取真实高度/移动底座尺寸，不能称完整实物复现。若实际底座突出必须计入外轮廓。同型号小车需真实模型和非圆几何验证，本阶段不将其当作.12m圆柱。

## 小目标感知核对：发现初始化/重建时的完整物体覆盖缺口

15份本机点簇重放全部匹配记录：5056次扫描时刻及4796次控制时刻预测检查，数值最大差0。离线真值仅用于外部目标径向标签和精度/覆盖诊断，不进入感知或控制。4–20s可标记外部目标帧每机约139–161帧，缺失或含糊帧不补零、不算准确预测。

多数本机目标速度RMSE约.0031–.0060m/s，但迎面3号约.01679m/s，斜向2/3号约.03332/.02455m/s。低误差不能覆盖重建失败：

- 迎面3号9.482–10.060s，7帧，新ID2处于MVEE、尚无可信圆先验；
- 斜向3号6.191–6.684s，6帧，新ID4处于MVEE；
- 斜向2号15.285–15.693s，5帧，新ID2处于MVEE。

这些18帧不是单纯保守证书未通过：用原日志的中心/半轴/方向与独立评估圆，在4096个边界采样中确认均存在规范化距离>1的点，最大约1.5569；加.13m物理车体代理与原.12m模型车体裕量后，也均存在包络外采样点。`physical_coverage_audit.json`及工具`audit_cbf_physical_circle_coverage.py`可复核。它是扫描时刻的仿真圆轮廓反例，不是实际发生碰撞；但说明只有可见面MVEE时，不能把原模型约束满足解释为完整物体安全保证。当前所有反例均为尚未获得可信圆的MVEE，不是已有圆先验保持分支丢失覆盖。

5951条已采用控制首步、三份误差及**测量**几何包含、25307项显示检查通过；该结果与上述完整物体覆盖反例不矛盾。首次/新ID的MVEE包住回波点，并不必然包住未看见的整个垃圾桶。故障零命令未自动认证。

## 后续优先顺序

因此先冻结本阶段基准，不直接把它当作已完成的五机版本，也不缩裕量或延长100ms截止来提高通过数。

1. 下一独立阶段针对已知.12m垃圾桶设计**初始化/重关联时的尺寸先验与中心不确定性估计**：尺寸来自实物标定，不能读取Gazebo中心/速度；保持原点簇诊断、身份和质量门槛，对稀疏/遮挡/未获得可信圆的情况明确处理。此项尚未实现，不能说当前已修复18帧反例。不能把固定垃圾桶尺寸套给未知障碍或小车。
2. 分解输入准备、NLP、求解后校验与调度耗时，改善原100ms内完成率；不先靠更换语言/求解器或调大截止掩盖问题。
3. 在感知模型和运行预算稳定后，改五机绕行侧别/回归协调，继续使用各自scan和邻机小状态，不共享原始点云。保留R=.4及原互避边界。

这些是后续研究方向，不是已实现贡献或稳定性结论。
