# 批量数值计算与有预算的参考搜索（2026-11-04）

本阶段从 `cef3a33` 继续，所有修改仍在研究副本。原工程、main、CV 默认及此前各失败版本保留。原始结果在工作空间根目录 `四脚本对比证据/数值计算与预览预算_2026-11-04`，独立归档在 `阶段成果归档/2026-11-04_数值计算与预览预算`。本阶段优先改闭环效果，不将已看过种子当作未见验证。

## 排查与修改

上一阶段五机最长约 483 ms 的周期没有启动 IPOPT，其中约 401 ms 花在参考预览，不能归因为求解器单独耗时。首轮只改计算后，五机最高控制耗时约 108 ms，但动态代理净距仍约 −3.1 cm：计算变快没有自动解决避碰。

### 批量计算，保持原公式

- 对同一快照的中心、长短半轴、角度及 gamma 一次打包；椭圆 h 在障碍物／节点维度批量计算，控制候选在候选维度批量筛选。
- 局部参考复用同一预测数组与控制网格，不逐步重复构造障碍物字典；标量限幅保留 NaN 语义。
- 不保留跨传感器更新的隐式缓存，避免旧包络混入新帧。
- 独立标量公式与 8 条冻结参考检查控制、状态、评分和可用性；原 NLP 的动力学、优化变量、速度边界及 DCBF 公式没有改写，也没有更换 IPOPT。

### 控制预算内保留完成的候选

参考预览默认预算 25 ms，仍沿用控制 100 ms／NLP 65 ms。它是循环节点上的协作式检查，不能中断任意原生调用或操作系统调度，不是硬实时保证。

V1/V2 发现：危险阶段可以连续撤销整轮参考，因为四个长预览尚未全部完成预算就已耗尽。V3 开启 execution_backup 后默认优先生成原 MPC 1 s 窗口中的 cw/ccw 参考；先查上一可行方向，再查另一侧。完成且通过原窗口检查的候选会保留，另一侧超预算时不将前者丢弃。

记录中 `preview_scope=mpc_window`、`bounded_local_reference=true`，以及 `search_complete` 标明是否两侧都完成。只比较已完成候选，不能称全局最优或完整四候选搜索。每周期仍从新状态重新检查前缀；未完成的控制／状态数组不会返回。局部可行不等于 4 s 可行，也没有递归可行性／必然脱困证明。

长预览原实现保留：在 `/cbf/mpc` 配置中设 `bounded_local_reference: false` 可使用此前的长预览策略；冻结版本也在独立源码快照中保留。没有改变领导者、观测器、编队偏移、障碍位置、任务窗口或误差公式。

### 明确区分不可行时的尽力动作

新增独立开关 `infeasible_escape`，默认 false，要求 realtime_solver 与 execution_backup 同时开启。它不改变原 NLP；只有 NLP 没有返回通过检查的解、有限控制网格也没有原一步可行候选时才可能采用。

有限网格中的选择优先提高最差原一步 DCBF 残差，并要求优于零控制至少 2e-6。它维持输入边界；对于当前安全、且零控制下一节点仍能保持安全的屏障，拒绝新进入。若没有符合这些条件的改善动作，仍不输出逃逸候选。

**这种动作可能不满足原 DCBF。** 日志使用 `best_effort_escape`、`validated_steps=0`、`success=false` 和实际负残差，不把它归为可行后备或成功求解，不生成已采用辅助规划指标。它仅是模型不可行时的应急研究选项，有限网格没有候选不证明连续控制集合为空，也未证明尽力动作能避免实际碰撞。

场景 `evaluation.passed` 沿用原净距／终端误差等验收，不能解释成全程满足 DCBF；尽力动作和超时单独列出。所有原始失败继续保留，不能只取净距为正的运行宣传安全保证。

## 使用研究副本

默认 CV、progress_guidance=false、execution_backup=false、infeasible_escape=false。以下显式开启的实验只在隔离 Gazebo 验证；不是默认实物方案。

```bash
source /opt/ros/noetic/setup.bash
source devel/setup.bash

  scenario:=mixed prediction_mode:=adaptive gazebo_seed:=239 total_time:=40 \
  progress_guidance:=true execution_backup:=true infeasible_escape:=true
```
