# 邻机回归通道候选

父版853bfca，独立分支`research/peer-recovery-corridor-2026-11-26`。原同步/后台入口均默认关闭新机制；独立`five_turtlebot3_cbf_peer_recovery.launch`开启，默认仍五机R.4、桶R.12、原Gaussian雷达σ.01、CV、一步补偿后台IPOPT与100ms截止。修改前源码已独立保存，原工程src/main/旧档案保持。

针对绕行落后后挤入邻机之间的现象，增加本机参考候选：保持当前侧向车道、沿当前侧别向邻机带外侧让出通道，以及3/4.5/6s平滑回归。外侧位置由现有peer包络沿横向的支持半径＋原车体裕量＋.03参考余量构建，不改变实际硬安全边界。加速追赶不能永远是唯一选择，故参考构造同时考虑.10m/s、当前名义速度、原上限.22m/s三档限幅；这是参考候选，不缩原优化器速度范围，不强制实际最低速度。每个候选都要求3s预览中最低1s路程速度≥.09m/s，禁止把停住候选当有效参考。

原领导者观测、定时目标、编队偏移和误差公式不变，原N10/dt.1、v±.22、omega±2.84、q界与DCBF容差2e-6、原恢复gamma规则保持。候选原1s硬前缀必须通过原障碍预测/原DCBF，最终优化/后台结果仍用最新真实测量与当前原约束再验。3s邻机预览只在原窗口后沿末端预测速度、保持最后半轴作软排序，原窗口内保留原预测节点；不是3s硬安全保证或协作预测准确性证明。

通道不合适时保持移动车道或选择有实际侧移的较慢回归，空间与纵向同时协调；没有合格候选则撤销本项附加参考、回原方案，不假装求解出可行控制。原1s硬约束仍始终有效，最终无合格命令依旧计保护失败。已经挤入不可行状态不能靠事后小参考修复。活动外部避障通常由原方案处理；仅明显落后且已发生侧移时允许尝试保持/外侧参考，新提前回归仍受原外部回归资格约束。

只用已接收的邻机里程计/本机雷达包络，不共享雷达、点云或新增ROS通信。新增`recovery_stamp`来自本机当前采样时间，后台补偿时同步前推.1s，并随输入落盘，不能把后台旧状态当当前状态。软选路、独立机器人互相适应和末速度预测均无可行性/活性理论保证；可能增加绕行宽度、恢复时长或保守性，须保留负结果。

验证顺序：专项/完整回归，旧迎面同输入条件可行性诊断，然后冻结源码；先迎面40s/seed211检查有无新代理碰撞和原首步/当前完整候选审计，再原追越、斜向同配置各一次。全部结果保存，不改原.075m/s、停顿、100ms、净距和恢复验收门槛。旧片段不是新闭环，不能声称同输入前缀可行就证明原停车已修复。启动崩溃单独记录，新目录重试，不覆盖旧结果。没有新GUI或实物验证授权外操作。

## V1结果与V2运动方向一致性

V1冻结c801379，284项检查通过；原网格、外侧补充、纵向档位等开发日志全部保留。旧迎面30个固定输入诊断中，纯保持/外侧版没有合格候选，增加纵向选择后仅19.61s一个前缀合格，不能作为“旧停车已修复”证据。新三类40s实际完成、代理净距为正，但严格0/3，迎面0号24次保护停车、最长停住2.245s，比父版退化，不接受V1替换。

旧输入显示机器人在14–16s身体朝向由−1.97变到−3.13rad，实际v约−.15m/s，正沿世界前向倒车移动；原参考生成器仅构造正v，转向过程中参考路程速度可能接近0而被筛掉。这是参考族的可行性局限，不是原优化器不允许倒车，也不把全部失败单独归因该现象。

V2新增独立可选`peer_recovery_signed_chart`。身体背向行进方向时使用严格的非完整模型对称变换θ′=θ+π、v′=−v、ω′=ω生成参考，再映射回实际θ/v；半隐式离散模型中同样逐步保持xy轨迹和实际控制动力学一致。目标/领导者朝向不变、原实际v±.22及omega约束不变、原增量界若启用同样检查。参考生成兼容原本已允许的倒车，不能把变换当新的安全定理或求解器。

V1与旧入口默认关闭该开关，V2测试显式开启；仍预定五机迎面/追越/斜向各40s一次，原验收不变。额外报告末朝向误差，不能只看位置恢复就宣称朝向也恢复。仍可能有回归冲突和末速度假设偏差，全部失败保留。闭环与采用结论待实测后追加。

## 诊断与后续边界

当前新增的是各机器人独立的局部参考选择，**没有实现邻机意图交换、优先级协商或共同形变**。把邻机末速度延长到3s只是假设；邻机自己也在重新规划时，该假设会偏离。保持/外移/较慢回归虽然可能避开当前交集，仍可能造成保守滞留、回归过晚和误差积累。参考族支持倒车解决的是表示局限，不解决多机同时回归的整体可行性/活性。

因此保留该候选用于消融和后续对比，**不提升、不开启旧入口默认值、不替换853bfca父版**。旧`five_turtlebot3_cbf_local_worker.launch`/名义入口中的`peer_recovery_corridor`和`signed_chart`均默认false，保持父版路径可用。上面的新实验入口是负结果复现入口，不是推荐演示命令。

下一项更合理的研究是少量参数的避让/回归意图协调，例如阶段、侧别、期望侧向形变和时标，继续各机自己处理雷达，不交换原始点云；先复现0号落后并挤入2/3号之间的片段，再验证协调是否实际保持运动和恢复队形。尚未实现/验证该通信机制，不能提前计为论文贡献，也不能仅增加优先级标签就声称解决可行性。
