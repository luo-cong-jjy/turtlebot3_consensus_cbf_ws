# 可行初始化、后备控制与局部绕行（2026-11-04）

本阶段优先改善闭环效果，在独立研究副本推进。原工程、CV、以前的参考候选及全部失败记录保留。新增 `execution_backup` 默认关闭；它是实验开关，不代表已完成安全证明或实物验证。

## 改动

1. 在长参考预览和 NLP 之前，先对有限控制网格进行原一步速度／增量界及 DCBF 筛选，再用原数值校验器确认。NLP 失败后可以返回已经检查的首个控制；重复该控制并不意味着整段可行，日志仍标记 `validated_steps=1`。
2. 对移位后的上一控制和可用预览前缀，在当前测量状态、当前预测包络及上一实际命令下重新做全窗口验证。用原 CasADi 符号目标函数评价通过者，作为可行初始化／全窗口后备；如果 NLP 给出成本更大的可行解，保留较好的已检查候选。仍然每周期最多求解一次 NLP。
3. 预览包含允许倒车的车身朝向。启用本开关后将该朝向单独传给软目标，避免用反向平移速度的角度代替车身朝向。
4. 优先保留原 4 s 长预览。其不可用，或已选绕行方向仅长预览不可用时，可尝试原 MPC 1 s 窗口中的局部绕行：逐步以有限网格调整参考控制，使其满足相同的下一节点 DCBF；整段还须通过原窗口检查与已有运动假设均值检查。局部候选仅允许 cw/ccw，不能把等待／直接跟踪重新命名为绕行。日志明确记录 `preview_scope=mpc_window`。
5. 直接恢复受阻时保持仍可行的环绕方向。允许原窗口已不可行时换侧；长窗口中若旧方向成本大于最佳可行候选的 `2 倍 + 0.25`，也允许退出保持，以免固定绕远。这是明确的启发式阈值，不是推导出的最优条件。不能仅因长外推失败就来回换侧。方向保持不是永久侧别承诺或必然脱困证明。
6. IPOPT 迭代回调在启用时改为每次迭代检查期限，并为后备和发布预留更多时间。仍是协作式停止，不能中断单次原生计算／操作系统调度，不能保证每次都在 100 ms 内完成。

没有更换求解器、优化变量、领导者观测／编队偏移、场景位置、速度硬界或 DCBF 不等式。`delta_limit` 仍沿用原配置，默认 false；本阶段没有新增硬加速度限制。原误差定义和结果图类别保留，评价仍为 schema 2。

## 使用

从研究副本执行，先确认 `rospack find` 指向研究副本：

```bash
source /opt/ros/noetic/setup.bash
source devel/setup.bash
rospack find tb3_distributed_control
roslaunch tb3_distributed_control single_turtlebot3_cbf_dynamic.launch \
  scenario:=decelerating_crossing prediction_mode:=adaptive gazebo_seed:=211 \
  progress_guidance:=true execution_backup:=true total_time:=32

# 五机器人入口同样支持这两个开关
roslaunch tb3_distributed_control multi_turtlebot3_consensus_gazebo_cbf_dynamic.launch \
  scenario:=mixed prediction_mode:=adaptive progress_guidance:=true execution_backup:=true
```

单独关闭 `execution_backup` 可保留此前参考候选的行为；关闭 `progress_guidance` 则不启用长／短动态参考机制。默认预测仍为 CV，没有自动将 adaptive 提升为默认。

## 结果边界

这些是已看过场景上的开发检查，不是未见数据或统计对比。固定 Gazebo 种子不保证进程调度、传感器／控制回调逐位相同；不同版本的单次结果不能归因为严格配对因果效果。

后备只针对当前模型与采样节点做有限数值检查，未证明递归可行性。预测／几何变化可能使当前状态已处于模型包络内；有限网格没有候选也不证明连续控制集合为空。没有可用控制或控制过晚时，控制器仍可能强制停止，零控制在动态场景中并非安全证明。真实净距这里只是约 20 Hz 的圆形代理，不是连续物理安全结论。短窗口参考也不等同于通过了 4 s 检查。

最终开发结果及验证记录见 [阶段摘要](stages/execution_backup_validation_2026-11-04.json)。实物与更广泛场景留待后续，不把有限仿真通过直接当成论文贡献已经成立。
